# 第一篇周总结

> 这是我在vibe coding 第一周的学习

## 💡 核心感悟

**Vibe Coding 的理解比执行更重要。** 使用现有技能能够显著提高效率，自创技能需要在吃透之后再考虑本地化适配调整。

## 📝 本周收获

### 0. 第一次 0→1 Vibe Coding 复盘

**项目**：智能客服系统 v1

**结果**：失败

- **前端**：未达预期，聊天界面交互简陋，组件结构混乱
- **后端**：一直报错，API 联调困难，（数据库仅有表，空数据竟然不报错）
- **唯一稳定的**：Docker Compose 编排（MySQL + Qdrant + Redis 容器全部正常运行）

**反思**：0→1 的项目不能全靠 AI 生成代码，需要人先理清架构再逐步实现。AI 擅长局部优化，但不擅长全局把控。

### 1. 技能使用经验

- **善用现有技能**：优先使用社区成熟技能，减少重复造轮子
- **谨慎自创技能**：自创技能需要先理解原理，再进行适配调整
- **警惕过时配置**：Vibe Coding 生成的初始化配置（尤其是配置文件）一定要检查和验证，避免使用几年前的过时参数

### 2. Docker Compose 实战

#### 批量创建 Services

以前习惯用单独的文件对应每个服务，本周学会了在 `docker-compose.yml` 中批量管理服务。

#### Windows 时区映射问题

- **问题**：Windows 下文件夹映射和 1Panel 环境配置有差异，时区映射一直报错
- **解决**：暂时移除了时区映射，仅在环境配置中设置了 `Asia/Shanghai`
- **教训**：非自建生成的 docker-compose 初版要检查：
  - 各容器的版本兼容性
  - 存储卷路径是否符合宿主机系统
  - Windows/Linux 路径差异（`/` vs `\`）

### 3.其他作为规则加入到Claude.md

#### 跨平台路径规范

- 代码中（Python/JS）统一使用 `/` 分隔符，用 `pathlib.Path` 或 `path.join` 拼接路径，避免硬编码 `\`
- 配置文件（docker-compose.yml、nginx.conf 等）遵循对应工具的语法要求
- 文档中的路径引用使用正斜杠 `/`（如 `backend/app/services/`）
- 终端命令中：Windows 下注意 `C:\` 盘符，Linux 下为 `/home/` 等 Unix 风格路径
- 涉及文件读写时，始终以运行环境实际路径为准，不要假设 Windows 和 Linux 路径格式相同

#### Write 工具路径转义规范

- **file_path 必须使用正斜杠 `/`**：`c:/Code/...` 而非 `c:\Code\...`
- Windows 路径中的 `\` 在 JSON 中是非法转义序列，会导致 Write/Bash 工具参数丢失
- 如果路径包含特殊字符，优先使用**相对路径**（相对于工作目录 `c:/Code/Claude/ai-customer-service/`）
- Bash 命令中的路径同样使用正斜杠 `/`

## 🔍 待解决问题

### 写入失败现象

**问题描述**：频繁出现写入失败，需要排查根本原因。

**可能的原因**：

1. **写入工具问题** — 工具本身有限制
2. **Content 超长被截断** — 输入内容超过缓冲区上限

**探索中的三种方案**：

| 方案                | 思路                 | 难度       | 评价                 |
| :------------------ | :------------------- | :--------- | :------------------- |
| 一次性 Token        | 单次传输到位         | 治标不治本 | 简单但可能仍有上限   |
| 流式拼接 + 延迟解析 | 分片传输，累积后解析 | 主流方案   | 用的人多，可靠性较好 |
| AST 语法修复        | 从底层语法层面修复   | 最难但最好 | 一劳永逸，投入大     |

**下一步**：观察失败日志，确认是工具问题还是内容截断导致，再选择对应方案。
